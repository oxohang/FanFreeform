# Hyper手势（HyperGesture）

把 HyperOS 原生小窗、应用快捷方式和最近任务装进屏幕边缘手势。通过底角斜滑或侧滑即可选择目标，松手后以小窗或全屏方式启动；也可以进入蜂窝应用总览、Hyper 任务中心或系统任务中心。

当前版本：`1.0`（build 131）

> Hyper手势是依赖 HyperOS 私有接口的 LSPosed 实验性模块，不是小米、魅族或 Apple 的官方项目。不同机型和系统版本的内部接口可能不同，请先阅读兼容性说明并保留可用的模块禁用或救砖方案。

## 手势能力

| 入口 | 操作 | 界面 | 启动方式 |
| --- | --- | --- | --- |
| 底角一段 | 从左下角或右下角向内斜滑 | 扇形应用菜单 | 横竖屏分别选择小窗或全屏 |
| 底角二段 | 越过扇形范围继续向内滑动 | 全屏蜂窝应用总览 | 横竖屏分别选择小窗或全屏 |
| 侧滑 | 从侧边横向、斜向上或斜向下长滑 | 纵向列表、环形、扇形或蜂窝 | 应用类布局可选择小窗或全屏 |
| 侧滑任务 | 从侧边进入任务布局 | Hyper 任务中心或 HyperOS 系统任务中心 | 切换最近任务 |

短滑和未达到接管条件的手势会优先留给 HyperOS 返回操作。图标未被选中、手指回到取消区域或移入任务中心退出区域时，不会误启动应用。

## 主要功能

### 底角扇形

- 一段扇形和二段蜂窝可分别启用，竖屏与横屏独立配置。
- 支持智能排布、固定排布和最多三排的自定义内、中、外排容量。
- 可调整触发区域、分段距离、二段回退距离、选择范围、图标大小和目标数量。
- 呼出、图标旋转、选中放大、取消淡出、速度和扇形阴影均可独立调整。
- 可统一显示选中应用名称、启用震动反馈，或关闭强制圆形图标以保留应用原始轮廓。

### 侧滑手势

- 竖屏和横屏可分别启用，并分别选择列表形式与启动方式。
- 支持横向向内、斜向上和斜向下三种方向。
- 提供顶部安全距离、触发距离、反向取消距离和蜂窝停留时间。
- 纵向列表、环形、扇形共用独立的侧滑目标清单；蜂窝使用蜂窝目标清单。
- 列表可跟随手指出现，并支持独立图标大小、环形尺寸、应用名称和呼出动效。
- 只有当前方向选择蜂窝布局时，蜂窝停留触发才会生效。

### 蜂窝应用

- 支持普通应用和快捷方式，可供底角二段与侧滑蜂窝布局共用。
- 两种操作方式：浏览模式支持松手后继续拖动、缩放和点击；按住滑选模式在松手时直接启动当前目标。
- 蜂窝圆盘可跟随手指出现，也可固定在自定义屏幕位置。
- 默认使用壁纸高斯模糊背景，也可切换纯黑背景并调整模糊和压暗程度。
- 可调整圆盘大小、图标大小、蜂窝间距、目标数量和选中名称显示。
- 凸面镜式动效支持惯性、中心凸起、边缘缩放、选中放大和动画速度调节。

### Hyper 任务中心

- 侧滑呼出横向最近任务，移动到目标后松手切换应用。
- 支持带实时任务预览的横向卡片模式，以及只显示运行应用的横向图标模式。
- 可调整最近任务数量、卡片宽高、圆角、图标大小、图标间距和卡片与手指距离。
- 可选应用名称显示，并提供下移选择容错，减少手指横划时轻微下移造成的丢失选中。
- 跟手速度、吸附、放大和回弹动效可单独调节。
- 也可让侧滑直接进入 HyperOS 自带任务中心，并选择隐藏系统任务中心的清除按钮。

### 应用与快捷方式

- 底角、侧滑和蜂窝使用独立目标清单，互不覆盖。
- 选择器支持搜索、批量勾选、全选结果、反选、清空和统一保存；已选项目自动置顶。
- 支持 Android 动态、静态、固定和缓存快捷方式。
- 通过小米桌面 Hook 读取桌面创建的快捷方式，并优先显示快捷方式自己的图标和角标。
- 通过 `LauncherApps` 目录读取可用启动入口，包括系统能够提供的应用双开入口。

快捷方式和双开能力依赖当前小米桌面及系统接口。如果目标没有出现在列表中，可先进入“杂项设置”热重载 Hook，再刷新选择器并导出兼容性报告。

### 小窗位置与尺寸

- 竖屏小窗和横屏小窗分别控制；任一方向关闭后完全交由 HyperOS 管理。
- 默认按 HyperOS 原生小窗尺寸做等比例整体缩放，避免固定屏幕比例导致横屏应用变形。
- 也可以关闭等比例模式，分别调整宽度、高度、水平位置和垂直位置。
- 底角一段、底角二段和侧滑可按方向选择小窗或全屏启动。
- 启动时优先复用已有任务，并尽量保留当前应用作为小窗背景。

### 窗外点击

- 竖屏和横屏分别启用；关闭的方向会移除 Hyper手势触摸层，恢复 HyperOS 原生行为。
- 小窗上、下、左、右外部统一视为一个区域，不再划分上下或左右功能区。
- 单击和双击可分别设置为：无操作、关闭小窗、挂起到右上角、全屏或小窗贴边。
- 单双击判定时间可调；时间越短单击越快，时间越长双击越容易识别。
- 系统返回侧滑保持更高优先级；输入法存在时，第一次窗外点击先收起键盘。
- 状态栏、控制中心、小窗移动、缩放、贴边和挂起期间会重新仲裁或暂停触摸层，避免操作穿透和残留遮罩。

## 设置页地图

| 一级页面 | 主要内容 |
| --- | --- |
| 启用手势 | 总开关、震动、统一名称显示、图标形状 |
| 底角斜滑 | 横竖屏一段/二段、触发与选择、应用清单、扇形排布和动效 |
| 侧滑手势 | 横竖屏布局与启动方式、方向、安全距离、应用清单和动效 |
| 蜂窝应用 | 目标清单、浏览/按住模式、位置、背景、圆盘布局和凸面镜动效 |
| 任务中心 | 卡片/图标模式、任务数量、尺寸、选择容错和切换动效 |
| 小窗位置设置 | 原生比例缩放、独立宽高与横竖屏位置 |
| 窗外点击设置 | 横竖屏开关、单击/双击动作和判定时间 |
| 杂项设置 | Hook 热重载、兼容性报告、系统任务清除键和桌面图标 |

每个主要设置页面底部都提供带确认提示的“恢复默认设置”。

## 默认行为

- Hyper手势和震动反馈默认开启。
- 底角竖屏一段扇形、二段蜂窝默认开启；底角横屏默认关闭。
- 侧滑竖屏默认开启并使用蜂窝布局；侧滑横屏默认关闭。
- 竖屏自定义小窗位置默认开启，横屏默认交由 HyperOS 管理。
- 竖屏窗外点击默认开启：单击关闭小窗，双击小窗贴边；横屏窗外点击默认关闭。
- 蜂窝默认使用按住滑选、固定位置和壁纸高斯模糊背景。

所有默认值都可以在对应页面修改或恢复。

## 使用要求

- 已解锁并取得 root 权限的小米设备。
- 已安装并能正常工作的 LSPosed。
- HyperOS 3；其他版本需要根据兼容性报告单独适配。
- LSPosed 作用域同时勾选：
  - 系统界面：`com.android.systemui`
  - 小米桌面：`com.miui.home`

主要验证环境：小米 `2509FPN0BC`（`popsicle`）、HyperOS `OS3.0.317.0.WPBCNXM`、Android 16。该记录只代表已验证环境，不代表所有 HyperOS 3 版本均兼容。

## 安装与首次配置

1. 正式发布后从 GitHub Releases 获取签名 APK；当前也可以自行构建 Debug APK。
2. 安装后在 LSPosed 中启用 Hyper手势，并勾选系统界面和小米桌面。
3. 打开 Hyper手势，在“杂项设置”点击“一键重载 Hook 进程”。该操作只重载 SystemUI 和小米桌面，不会重启手机。
4. 确认首页 Hook 状态已连接。
5. 分别进入底角、侧滑或蜂窝页面，选择应用与快捷方式。
6. 先使用默认参数测试，再根据手感调整触发距离、安全区域、选择范围和动画。

若隐藏了桌面图标，仍可从 LSPosed 的模块设置入口打开，或使用 `hypergesture://settings` 深层链接。

仓库不跟踪 APK。公开安装包应通过 GitHub Releases 提供，并使用维护者长期保存的正式证书签名。如果设备曾安装其他证书签名的开发版，需要先卸载旧版或继续使用相同证书。

## 兼容性与排查

Hyper手势会注入 SystemUI 和小米桌面，并调用 HyperOS 自由窗口、手势与任务管理私有接口。下列情况可能需要单独适配：

- SystemUI、系统桌面或自由窗口服务类名和方法签名发生变化；
- 系统或目标应用禁止自由窗口；
- 第三方主题、导航模式或其他手势模块改变触摸层级；
- 应用双开、桌面快捷方式目录在当前桌面版本不可读；
- 厂商更新改变状态栏、控制中心、输入法或最近任务行为。

出现问题时：

1. 确认 LSPosed 中两个作用域都已勾选。
2. 在“杂项设置”执行 Hook 热重载。
3. 点击“一键导出兼容性报告”。报告包含系统、桌面、Hook 状态、缺失接口和配置摘要，不包含联系人或快捷方式内容。
4. 使用 [Bug 反馈模板](https://github.com/oxohang/FanFreeform/issues/new?template=bug_report.yml) 提交设备版本、复现步骤、兼容性报告和相关日志。

上传前仍请自行检查报告和日志，移除不希望公开的设备信息。

## 构建

需要 JDK 17 和 Android SDK：

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Debug APK 位于 `app/build/outputs/apk/debug/`。构建生成的本地归档位于 `release-archive/`，该目录不会提交到 Git。

## 正式签名

Release 构建不会使用 Android 调试证书。通过环境变量或本机未跟踪的 Gradle 属性提供以下值：

```bash
export HYPERGESTURE_KEYSTORE=/absolute/path/to/release.jks
export HYPERGESTURE_STORE_PASSWORD=your_store_password
export HYPERGESTURE_KEY_ALIAS=your_key_alias
export HYPERGESTURE_KEY_PASSWORD=your_key_password
./gradlew :app:assembleRelease
```

未提供完整签名配置时，Gradle 会生成 unsigned release，便于 CI 或本地验证，但不能直接安装发布。不要把 keystore、密码、`local.properties` 或本机 Gradle 配置提交到仓库。
