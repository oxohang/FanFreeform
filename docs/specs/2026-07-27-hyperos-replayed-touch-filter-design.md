# HyperOS 底部手势回放事件过滤设计

## 问题与证据

模块在热区 `ACTION_DOWN` 第一帧调用 `pilferPointers()` 时，HyperOS 底部导航组件尚未观察到有效位移。导航组件收到取消后会走点击回放兜底，向当前应用注入一组 `ACTION_CANCEL + ACTION_DOWN + ACTION_UP`。这组事件沿用本次真实手势最初的 `downTime`，事件时间早于模块已经处理过的移动事件。全局输入监听也会再次收到它们，旧实现会重置当前扇形，导致显示约 100ms 后立即消失；只过滤回放又会遇到部分手势不再收到真实最终 `UP`，无法完成选择。

扇形覆盖层自身带有 `FLAG_NOT_TOUCHABLE`，不是输入被覆盖层截走。

## 方案比较

- 透明底角捕获窗配合按下即 pilfer，并按时间序列过滤残余回放（最终采用）：物理触摸从起点就命中模块的系统级透明窗口；模块在第一帧取消小白条的独立全局监听，而真实触摸目标仍持续收到完整事件。时间过滤器继续作为 ROM 异常事件的保险。
- 固定时间防抖：显示后 200–300ms 内忽略抬手。实现简单，但会吞掉快速选择的真实抬手并增加操作黏滞感。
- 强制最短显示时间：只延迟视觉隐藏，内部状态仍可能被回放事件重置，无法从根本上保证选择连续性。

## 事件规则

- 有效热区由系统级透明窗口直接接收，`DOWN` 建立手势身份并进入待判定状态。
- 首个达到方向决策距离且朝内斜上的移动显示扇形；透明窗口会持续持有触摸目标直到真实终止事件。
- 当前手势尚未结束时，若再次收到相同 `downTime` 的 `DOWN`，视为系统回放并忽略。
- 相同 `downTime` 的 `UP` 或 `CANCEL` 若 `eventTime` 早于已处理的最新事件，视为系统回放并忽略。
- 时间继续向前的真实 `MOVE`、`UP`、`CANCEL` 照常处理；真实抬手仍立即选择或取消。
- 新手势使用不同的 `downTime`，仍可正常重置旧状态并开始。
- 手势正常完成、取消或异常复位时清除时间身份。

## 验证

- 单元测试覆盖重复 `DOWN`、倒退的 `UP/CANCEL`、正常后续移动、真实抬手、新手势与复位。
- 单元测试、lint 与 Debug APK 构建通过。
- 真机复现时应记录“底角捕获窗收到按下”和完整的真实移动、松手；若 ROM 仍产生回放，则应额外记录“忽略 HyperOS 回放边界事件”。扇形保持显示直到用户真实松手。
