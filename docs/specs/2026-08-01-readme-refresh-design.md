# Hyper手势 README 更新设计

## 目标

将仓库首页从早期“随用随走 / FanFreeform”说明更新为 Hyper手势 1.0 的真实产品说明。README 以普通用户快速理解和正确安装为第一优先，同时保留开发者构建、签名、兼容性排查和开源许可信息。

## 方案选择

采用“普通用户优先的分层说明”：顶部给出产品定位、兼容范围和核心入口；中部说明各手势模式、窗口能力和设置结构；底部再放构建、正式签名、问题反馈及许可证。

不采用纯功能百科式结构，因为大量参数会掩盖主要使用路径；不采用开发者优先结构，因为仓库公开后的主要读者首先需要判断设备是否兼容、模块能做什么以及如何启用。

## 名称与定位

- 中文正式名称统一为“Hyper手势”。
- 英文标识使用“HyperGesture”。
- `FanFreeform` 仅作为旧仓库名和内部历史标识，不再出现在标题或产品介绍中。
- 明确这是 HyperOS 3 的 LSPosed 实验性模块，不是小米、魅族或 Apple 官方项目。

## README 结构

1. 标题与一句话定位：说明底角斜滑、侧滑、蜂窝和 HyperOS 原生小窗。
2. 当前版本与兼容性：标明 1.0 build 131、主要验证环境、root/LSPosed 和两个 Hook 作用域。
3. 手势能力总览：用表格对比底角一段、底角二段、侧滑和任务中心的界面、启动方式与关键配置。
4. 核心能力：应用与快捷方式、动效、小窗尺寸位置、窗外点击、横竖屏独立配置、兼容性报告。
5. 设置页地图：按应用一级菜单列出设置归属，让用户能快速找到参数。
6. 安装与首次启用：安装、勾选作用域、热重载 Hook、选择应用、调整手感。
7. 已知边界与排查：强调 HyperOS 私有接口、不同版本兼容性、失败时导出报告和提交 Bug。
8. 构建与签名：保留 JDK 17、Android SDK、Gradle 命令和私钥环境变量说明。
9. 文档与许可证：链接关键设计资料并声明 GPL-3.0。

## 内容边界

- 只描述当前 1.0 源码中已经存在的功能，不加入路线图或未实现承诺。
- 不公开收款码、个人联系方式、本机路径之外的隐私信息或 APK 二进制。
- 不宣称所有 HyperOS 3 设备均兼容；兼容性结论以当前验证设备和导出报告为准。
- 不把每个滑杆范围写入 README，避免设置变化后文档再次失真；只说明参数类别和默认行为。
- 不添加无真实 CI 支撑的构建状态徽章，也不使用尚未准备好的截图。
