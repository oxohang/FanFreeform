# HyperGesture 手势设置重组设计

日期：2026-07-31

## 目标

将不断增加的手势设置按功能职责重新归类，使用户先选择功能，再配置行为、触发参数、应用和动效。横屏与竖屏行为独立；功能开关、启动方式和动画参数不在同一页面混排。

本次只重组设置结构并补齐已确认的横竖屏独立配置，不改变现有手势的核心操作方式。

## 设计原则

1. 一级页面代表一个完整功能，不按参数类型堆叠。
2. 行为设置回答“是否启用、如何启动”；触发设置回答“怎样触发”；动效设置只回答“怎样显示”。
3. 底角斜滑保留一段扇形和二段蜂窝；侧滑只有一段，不出现二段相关设置。
4. 横屏和竖屏的启用状态、启动方式及侧滑布局互相独立。
5. 现有用户配置尽量原值迁移；新增横竖屏配置不得默认开启原先未启用的横屏功能。

## 一级菜单

首页按以下顺序展示：

1. 启用手势
2. 底角斜滑
3. 侧滑手势
4. 蜂窝应用
5. 任务中心
6. 小窗位置
7. 窗外点击
8. 杂项

不增加全局“动画与外观”入口。动画归入所属功能的二级页面。

## 启用手势

保留全局总开关和真正跨手势共用的选项，例如震动反馈、图标形状及桌面图标显示。此页面不放具体手势的距离、布局或动画参数。

## 底角斜滑

底角页只展示入口和当前状态摘要，不直接铺开全部开关与滑杆。

### 竖屏行为

- 一段手势开关。
- 一段启动方式：小窗或全屏；仅在一段启用时显示。
- 二段手势开关。
- 二段启动方式：小窗或全屏；仅在二段启用时显示。

### 横屏行为

配置项与竖屏一致，但使用独立配置值。横屏默认保持关闭，避免升级后改变现有操作。

### 触发与选择

- 底角触发区宽度和高度。
- 第一段触发距离。
- 第二段蜂窝触发距离。
- 从二段返回一段的回退距离。
- 扇形图标选择距离。
- 其他直接影响手势判定的安全距离参数。

### 应用与扇形排列

- 小窗应用与快捷方式入口及已选数量。
- 扇形图标大小与目标上限。
- 智能排列、固定排列和自定义排数。
- 排列顺序继续遵循内排、中排、外排。

蜂窝应用不在这里重复管理，统一由“蜂窝应用”一级页面管理。

### 扇形动效设置

- 动效总开关和速度。
- 图标呼出幅度、旋转幅度。
- 选中放大、确认动画和取消淡出。
- 扇形背景阴影及阴影范围。
- 与扇形视觉反馈直接相关的名称和选中标识。

## 侧滑手势

侧滑只有一段。页面和运行逻辑中均不得引入“侧滑二段”概念。

### 竖屏行为与布局

- 竖屏启用开关。
- 启动方式：小窗或全屏。
- 布局形式：纵向、环形、扇形、蜂窝或任务中心。
- 布局跟随手指或使用固定位置。

### 横屏行为与布局

配置项与竖屏一致，但使用独立配置值。横屏默认关闭；用户开启后可选择与竖屏不同的布局和启动方式。

### 方向与触发

- 横向、斜向上和斜向下方向开关。
- 顶部与底部安全距离。
- 触发距离和反向取消距离。
- 停留触发开关与停留时间。

停留触发属于同一段手势的触发方式，不代表第二段。仅当所选侧滑布局支持该行为时显示对应设置。

### 应用与快捷方式

- 纵向、环形和扇形共用一套侧滑应用列表。
- 蜂窝使用蜂窝应用列表，不与普通侧滑列表混用。
- 显示已选数量、应用上限和同步入口。

### 侧滑动效设置

- 布局呼出、选择放大、确认启动和取消淡出动画。
- 环形、扇形及纵向布局专属视觉反馈。
- 侧滑选中名称及选中标识。

图标大小、环形尺寸和选择命中范围仍属于布局与操作参数，不放入动画页面。

## 蜂窝应用

### 应用选择

- 蜂窝应用及快捷方式列表、已选数量和上限。
- 侧滑蜂窝与底角二段蜂窝共用此应用列表。

蜂窝不保存独立的全屏或小窗启动方式。实际启动方式由进入蜂窝的底角或侧滑方向配置决定，避免同一次操作存在两套互相冲突的设置。

### 位置与背景

- 跟随手指或固定位置。
- 固定位置坐标。
- 壁纸高斯模糊、背景明暗和状态栏覆盖策略。

### 圆盘布局

- 圆盘显示大小、图标大小和蜂窝间距。
- 圆形边界与边缘图标可选中范围。
- 当前选中应用名称显示。

### 蜂窝动效设置

- 动效速度、惯性和跟手强度。
- 中心凸起、边缘缩放、整体位移和聚焦放大。
- 图标进入、退出及应用启动动画。

## 任务中心

### 任务数量与行为

- 最近任务数量。
- 任务来源与系统任务中心入口。
- 空白区域退出行为。

### 卡片布局

- 横向平铺或苹果式堆叠。
- 卡片宽度、高度、圆角、手指偏移。
- 卡片名称显示。

### 任务中心动效设置

- 跟手速度和滑动增益。
- 吸附、回弹和堆叠位移动画。
- 卡片选择与启动动画。

## 其他既有页面

“小窗位置”“窗外点击”和“杂项”继续作为一级页面。小窗位置与窗外点击保持横竖屏独立开关；它们不接收手势动画参数。

## 配置兼容

1. 能继续表达相同行为的现有配置键保持不变，仅移动设置入口。
2. 新增横竖屏独立键时，首次读取从现有共享键迁移一次。
3. 竖屏继承当前实际值；横屏继承现有横屏启用状态，默认关闭。
4. 侧滑现有布局和启动方式迁移到竖屏；横屏仅在原横屏已启用时继承，否则保持关闭。
5. 恢复默认设置按所属页面生效，不清除其他页面的应用列表或行为配置。

## 界面规则

- 一级页面显示名称、简短摘要和当前关键状态，例如“竖屏：一段小窗 / 二段全屏”。
- 二级入口显示当前值，不要求用户进入后才知道配置状态。
- 关闭父级开关后隐藏或禁用其从属选项，避免产生看似生效但运行时无效的设置。
- 启动方式采用小窗/全屏二选一；启用状态使用独立开关，不把“关闭”混入启动方式。
- 每个页面底部保留带确认提示的“恢复本页默认设置”。

## 运行时配置模型

运行时应先读取当前屏幕方向，再解析对应手势行为：

- 底角：方向配置 -> 一段/二段启用状态 -> 对应启动方式。
- 侧滑：方向配置 -> 单段启用状态 -> 对应布局 -> 对应启动方式。

动画配置只影响覆盖层绘制和过渡，不得改变触发阈值、应用选择结果或启动方式。

## 验收标准

1. 首页不存在独立“动画与外观”入口。
2. 底角、侧滑、蜂窝和任务中心均有自己的动效子页。
3. 底角横竖屏可分别控制一段和二段，并分别选择小窗或全屏。
4. 侧滑横竖屏可分别控制启用状态、启动方式和布局；任何页面都不出现侧滑二段设置。
5. 动画关闭或调节不会改变手势触发、选择命中和应用启动类型。
6. 升级后竖屏现有行为保持不变，横屏不会被意外开启。
7. 所有页面的恢复默认只作用于本页声明的配置范围。
8. 单元测试覆盖旧配置迁移、横竖屏解析、底角分段解析和侧滑单段解析。
9. 真机验证覆盖竖屏/横屏底角、竖屏/横屏侧滑，以及每种启动方式至少一次。

## 非目标

- 不新增侧滑二段手势。
- 不改变现有底角和侧滑的手势轨迹。
- 不修改小窗窗外点击、遮罩或 HyperOS 小窗接口行为。
- 不在本次设置重组中新增动画效果。
