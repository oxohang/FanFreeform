# 侧滑距离扇形手势设计（2026-07-27）

## 目标

在保留现有左右底角斜上滑扇形手势的同时，增加可独立开关的左右整侧“短滑返回、长滑扇形”手势。短滑必须继续由 HyperOS 原生返回链路处理；长滑越过可配置距离后，取消本次返回并无缝进入应用选择。两个触发方式可以同时启用。

## 方案选择

### 采用：延迟接管系统返回

模块通过现有全局输入监听观察侧滑，但在达到长滑阈值之前不窃取指针。短滑松手仍由 HyperOS 完成原生返回及跟手动画。达到长滑阈值时调用 `pilferPointers()` 取消系统返回，再显示扇形。

### 未采用：整侧透明窗口拦截后模拟返回

该方案容易完全占有输入，但短滑只能在抬手后注入返回事件，无法保留 HyperOS 原生返回预览和跟手动画。

### 未采用：Hook HyperOS 返回手势内部状态机

该方案可以更深地修改返回进度，但依赖私有实现细节，系统小版本升级后失效风险高于输入监听方案。

## 设置

- 新增 `启用侧滑距离触发` 开关，默认关闭；它只控制新增模式，不关闭底角斜滑。
- 新增 `侧滑长滑距离` 滑块，以屏幕宽度百分比保存，范围 18%–50%，默认 30%。
- 原有 `触发距离` 继续只控制底角斜滑模式。
- 原有 `选择距离`、`图标大小`、震动与阴影设置由两种扇形共用。
- 总开关关闭时，两种手势都停用。

## 两种手势的空间分层

侧滑模式启用后，屏幕最外侧的系统返回窄条从上到下保持连续，宽度优先读取 `WindowInsets.Type.systemGestures()`，无有效值时使用 32dp。

为避免底角透明捕获窗口吞掉短侧滑，左右底角捕获区分别向屏幕内部平移一个系统返回窄条宽度，并留出 1dp 边界间隔；捕获区自身的配置宽度和高度不变：

- 左侧滑：从屏幕最左侧窄条开始向右滑。
- 右侧滑：从屏幕最右侧窄条开始向左滑。
- 左底角斜滑：从左侧返回窄条内侧相邻的底部矩形开始，向右上滑。
- 右底角斜滑：从右侧返回窄条内侧相邻的底部矩形开始，向左上滑。

侧滑开关关闭时，底角捕获区恢复到屏幕最外侧，与当前版本行为一致。

## 侧滑状态机

### 1. 候选

手指在左右系统手势窄条内按下时创建侧滑候选，记录侧边、起点、时间和当前任务。此时不窃取指针、不显示扇形，HyperOS 返回手势正常运行。

### 2. 原生返回

在长滑阈值前抬手，或始终没有形成有效向内横滑时，模块不执行任何动作，事件完整留给 HyperOS。短滑因此保持原生返回。

### 3. 方向过滤

有效侧滑必须持续向屏幕内部移动。达到阈值前，纵向偏移不得超过 `max(24dp, 横向距离 × 0.55)`。超出后模块取消侧滑候选但不窃取事件，让系统或当前应用继续处理。

### 4. 长滑接管

向内横滑距离达到配置阈值时：

1. 调用输入监视器的 `pilferPointers()` 取消本次 HyperOS 返回。
2. 只有接管成功后才进入扇形状态；清除窗外点击候选。
3. 按震动开关反馈一次。
4. 显示从当前侧边向屏幕内部展开的扇形。

越过阈值后不可退回系统返回，避免同一手势在两套状态间反复跳变。

### 5. 选择与释放

长滑接管后，手指继续移动到应用图标上完成选择。抬手仅在命中图标时打开小窗；没有命中则关闭扇形且不执行返回，实现“长滑后反悔”。多指、取消事件或屏幕状态变化均安全结束本次扇形。

## 侧边扇形布局

- 原点位于触发侧边与按下高度的交点。
- 左侧扇形向右展开，右侧扇形向左展开。
- 图标沿相对水平轴约 -55° 到 +55° 的圆弧等角排布，使首次动作是横向内滑，出现扇形后可自然向上或向下偏移选择。
- 使用现有选择距离和图标防重叠算法。
- 当起点靠近状态栏或导航栏时，圆弧中心只做必要的垂直平移，使所有图标和标签留在安全显示区内。
- 阴影开关同时作用于侧边扇形背景；图标选中规则与底角扇形一致。

## 与其他交互的优先级

1. 已经接管的侧边长滑或底角斜滑扇形。
2. 尚未接管的 HyperOS 左右返回手势。
3. 小窗外单击、双击。
4. 普通应用点按。

小窗存在时，侧边发生移动后窗外点击候选立即取消。短侧滑仍返回，长侧滑进入扇形；静止侧边点按仍可按当前窗外动作设置处理。

## 组件边界

- `SideGestureArbitrator`：纯 Java 状态判断，只处理起点、方向、阈值与决策，不依赖 Android UI。
- `FanRuntime`：协调侧滑、底角手势、窗外操作与输入接管。
- `FanTriggerCapture`：支持侧滑模式下的水平内移量，保持底角捕获能力。
- `GestureGeometry`：增加侧边扇形图标位置与命中计算。
- `FanOverlayView`：根据布局类型绘制底角或侧边扇形。
- 配置层与设置页：保存开关和独立距离，实时通知 SystemUI。

## 失败保护

- 输入监视器或 `pilferPointers()` 不可用时，不显示侧边扇形并保留系统返回。
- 读取不到系统手势宽度时使用 32dp 回退值。
- 配置变化、锁屏、多指和异常终止都会清理侧滑状态与覆盖层。
- 新增模式默认关闭，升级后不改变现有用户的底角手势位置与行为。

## 验证

### 单元测试

- 左右侧向内横滑达到阈值时只决策一次 `FAN`。
- 阈值前抬手不接管。
- 反向、纵向偏移过大、多指均不触发扇形。
- 侧边扇形左右镜像、顶部和底部安全区修正、图标命中正确。
- 开关关闭时底角捕获偏移为零，开启时偏移等于系统手势宽度加 1dp 间隔。

### 真机验证

- 微信等普通应用中左右短滑仍显示并完成 HyperOS 原生返回。
- 同一路径滑过长距离时返回被取消，页面不退出，侧边扇形出现。
- 左右两侧、屏幕上中下不同起点均可触发，图标不越界。
- 侧滑模式开启后，平移后的左右底角斜滑仍可靠触发且不切换小白条应用。
- 小窗存在时短侧滑优先于窗外动作，静止侧边点按仍执行窗外配置。
- 关闭侧滑开关后行为恢复为当前版本。
