# 多小窗恢复、数量上限与键盘有效区域设计（2026-07-27）

## 目标

修复模块只追踪一个小窗导致的多挂起恢复错误，使任意由 Hyper手势打开并挂起的小窗都能从系统挂起位置恢复到软件设置的小窗位置，并继续拥有完整的窗外单击、双击操作。同时增加可配置的小窗总数与挂起数量上限，默认均为 3；输入法显示时，键盘区域视为当前小窗的一部分，不触发窗外操作。

## 已确认的系统行为

- HyperOS 3 的系统服务 `MiuiFreeFormStackDisplayStrategy` 将手机模式的 `mDefaultMaxFreeformCount` 默认设为 2。
- 新增任务使数量超过该字段时，系统会选择一个旧小窗并调用原生退出流程，因此第三个小窗消失不是 Surface 或硬件限制。
- 同一套系统服务已有 4 个前台小窗的布局与替换逻辑；SystemUI 的 `MiuiFreeformModeAvoidAlgorithm` 按任务数组动态排列挂起小窗，没有把数量写死为 2。
- SystemUI 的 `MiuiFreeformModeController` 会报告输入法可见状态和高度；窗口 Insets 也提供实际 IME 区域。
- 当前模块只有一个 `ownedTaskId` 和一个 `trackedTaskId`。挂起 B 后会覆盖 A 的所有权，所以 A 恢复时不会重定向动画，也不会重新成为窗外操作目标。

## 方案选择

采用“多任务注册表 + 系统上限字段接管 + 模块 FIFO 挂起队列 + IME 独立有效区域”。

未采用只把系统上限从 2 改为 3，因为它不能修复旧挂起任务丢失恢复位置和窗外操作的问题。未采用只拦截系统关闭方法，因为系统内部仍会认为数量超限，后续任务排序和替换行为不稳定。未采用虚拟挂起队列，因为它不能让三个真实任务同时保留在 HyperOS 小窗系统中。

## 配置与功能页

主设置页新增“功能”入口，进入独立功能页。首版包含：

- `同时小窗个数`：控制 HyperOS 允许保留的总小窗任务数量，默认 3，范围 1–10。
- `同时挂起个数`：控制 Hyper手势管理的挂起小窗数量，默认 3，范围 1–10。

挂起数量不能大于同时小窗数量。用户降低同时小窗个数时，设置页同步夹紧挂起个数；配置读取端再次夹紧，避免旧配置或并发更新产生非法组合。

新增配置键：

- `maxFreeformCount`，默认 3。
- `maxSuspendedCount`，默认 3。

恢复默认设置时两项均恢复为 3。升级安装时不存在新键的用户自动使用默认值。

滚轮模式不属于本阶段功能页；其入口在后续侧滑阶段隐藏。

## 多任务注册表

### 数据模型

用按 `taskId` 索引的有序注册表替代单个 `ownedTaskId`。每个记录至少保存：

- 任务 ID 与包名。
- 当前状态：`LAUNCHING`、`NORMAL`、`SUSPENDING`、`SUSPENDED`、`RESTORING`。
- 最近一次状态更新时间。
- 进入挂起状态的顺序号，用于 FIFO 淘汰。
- 本次恢复应使用的全局小窗配置快照，或可重新计算的配置版本。

只允许 SystemUI Shell 主线程修改注册表，输入监听线程只读取不可变快照，避免恢复动画、任务回调和窗外操作并发覆盖状态。

### 任务归属

- 手势启动或复用旧任务时先记录待匹配包名。
- 匹配到对应 freeform 任务后加入注册表；同一任务重复匹配只更新记录，不重复计数。
- 模块管理的任务进入 mini 状态时保留在注册表并加入挂起队列。
- 任务消失、全屏或被原生关闭后从注册表和挂起队列移除。
- 短暂过渡状态保留 2 秒宽限；宽限结束后重新查询真实任务状态再决定清除，避免动画中误删所有权。

### 当前交互窗口

窗外操作只作用于当前处于 `NORMAL` 的模块小窗。任意挂起窗口被点击并恢复后，在其进入 normal freeform 状态时原子更新为当前交互窗口。其他仍挂起的任务继续保留所有权，但不参与窗外命中判断。

若当前窗口关闭、全屏或再次挂起，立即清除当前交互指针；不能把窗外点击错误地作用到另一个后台或挂起任务。

## 挂起与恢复

### 挂起上限

请求挂起当前窗口前清理已消失或已恢复的旧记录，然后计算真实挂起数量。

- 未达到上限：直接调用 HyperOS 原生 `fromFreeformToMini`。
- 已达到上限：选择挂起顺序最早的任务，调用 HyperOS 原生关闭流程；确认其离开 repository 或收到 task vanished 后，再挂起当前窗口。
- 旧任务关闭失败或在超时内仍存在：取消本次挂起，当前窗口保持 normal 状态，不强行制造第 `N+1` 个挂起任务。
- 被关闭的最早任务从注册表移除；其后重新打开时按新任务重新入队。

该 FIFO 规则已由用户确认：挂起第 4 个时关闭第 1 个，再挂起当前窗口。

### 恢复位置

系统 mini 恢复动画的目标计算不再只检查单个 owned task，而是检查任务是否存在于注册表且处于 `SUSPENDED` 或 `RESTORING`。

- 命中后用全局小窗大小和位置计算目标 bounds。
- 调用原生动画目标的 `setAnimParam`，动画与实际窗口都落在同一目标。
- 任务进入 normal 状态后设为当前交互窗口，并继续使用 repository 返回的实时 scaled bounds 进行窗外判定。
- A、B 同时挂起时，点击任意一个都独立恢复到同一个软件设置位置，不在右上角原地放大。

恢复仍使用 HyperOS 原生动画和 `restoreMiniToFreeformMode`，不额外绘制假窗口动画。

## 系统小窗总数上限

LSPosed 同时作用于 `android` 系统进程与 `com.android.systemui`：

- 在系统服务创建 `MiuiFreeFormStackDisplayStrategy` 后，将实例字段 `mDefaultMaxFreeformCount` 更新为 `maxFreeformCount`。
- 配置变化时更新现存实例，重启 SystemUI 或模块设置进程不是应用配置生效的必要条件。
- 仅修改普通小窗数量字段，不修改游戏专用上限、桌面模式固定上限、分屏/嵌入模式的安全分支。
- Hook 类或字段不存在时记录一次错误并保持 ROM 原行为；模块注册表仍按实际 repository 状态工作。

降低总数不会立即关闭现有任务，避免用户只调整设置就丢失工作。下一次创建新小窗前，模块按最早挂起、再最早模块小窗的顺序关闭超额任务，数量回落后再启动新任务。

### 首次生效边界

当前模块只作用于 `com.android.systemui`。升级后会新增 `android` 系统服务作用域；SystemUI 内的多任务恢复、FIFO 与键盘区域修复可通过单独重启 SystemUI 立即生效，但已经运行的 Android 系统服务不能在不重启进程的情况下补载新的 LSPosed 代码。

遵守“不重启手机”的部署要求，本次安装不主动重启 Android 系统服务，也不临时关闭 MIUI 优化来绕过限制。系统总数上限 hook 会在手机下次自然开机或系统服务自然重启时生效。首次安装当次应在功能页明确显示“系统服务重载后生效”，不能把尚未注入的数量 3 显示成已确认生效；其他 SystemUI 功能照常即时验证。

## 键盘有效区域

窗外判断从“单个小窗矩形”改为“有效区域集合”：

- 当前 normal 小窗的实时 scaled bounds 始终是有效区域。
- `WindowInsets.Type.ime()` 可见且高度有效时，将实际 IME 矩形作为第二个有效区域。
- 指针落在小窗或键盘矩形内时，不启动窗外单击/双击识别，也不向下层应用重放事件。
- 小窗与键盘之间的空白不自动并入有效区域；只有真实键盘表面范围属于小窗交互。
- 输入法隐藏、切换窗口或当前交互任务清除时，立即清除缓存的 IME 区域。
- 侧滑返回仍保持高于窗外操作的优先级，键盘打开时系统返回手势可以先关闭键盘。

优先读取当前窗口 Insets；若 ROM 回调时序导致短暂不可用，则使用 `MiuiFreeformModeController` 最近一次报告的可见状态和高度生成底部矩形。两者都无有效数据时只使用小窗 bounds，不猜测键盘范围。

## 故障保护

- 所有系统私有字段和方法调用均捕获异常，失败时保持 ROM 默认行为。
- 注册表设置容量上限为 8 条，清理无效任务后仍超限则丢弃最旧的无效记录，不无限增长。
- FIFO 关闭与新挂起串行执行，并设短超时；禁止在旧任务尚未退出时提前挂起当前窗口。
- SystemUI 重新启动后注册表为空。首次任务回调只接管由模块新启动或仍在待匹配窗口内的任务，不误接管用户手动创建的小窗。
- 系统服务进程的数量字段只接受 1–10，任何越界配置先夹紧。

## 组件调整

- `ConfigContract`、`ConfigStore`、`ConfigProvider`：新增两个数量配置。
- 新增功能设置 Activity，并从 `MainActivity` 提供入口。
- `GestureConfig`：读取、夹紧总数与挂起数。
- `HyperOsFreeformBridge`：多任务注册表、FIFO 队列、恢复目标重定向和当前交互任务管理。
- `FanFreeformHook`：在 SystemUI 保留现有 freeform hooks，并在系统服务进程安装数量字段 hook。
- `FanRuntime`：使用小窗 bounds 与 IME bounds 的区域集合执行窗外判断。
- `GestureGeometry` 或独立纯逻辑类：有效区域命中、配置夹紧与 FIFO 选择，便于单元测试。

## 验证

### 单元测试

- 配置默认值为 3，输入范围夹紧到 1–10，挂起数不超过总数。
- A、B 依次挂起后注册表同时保留两条记录，恢复任一任务都返回配置 bounds。
- 挂起队列达到 3 时选择最早的 A；A 移除后当前任务才能进入挂起状态。
- 任务 vanished、全屏和关闭都会从注册表及 FIFO 队列移除。
- 小窗区域和 IME 区域命中均返回内部，两者之间空白返回外部。
- IME 隐藏后旧键盘矩形不再生效。

### 真机验证

- 连续打开并挂起 3 个不同应用，三个任务均保留且 SystemUI 无崩溃。
- 第 4 个小窗出现时不会被 HyperOS 自动关闭旧任务；第 4 次挂起会关闭最早挂起的第 1 个。
- A、B 同时挂起后分别点击 A 和 B，两者都以原生动画恢复到设置位置，而不是在右上角原地放大。
- 每次恢复后，小窗四周任意窗外区域的单击、双击均继续生效，不穿透下层应用。
- 微信小窗打开键盘后可以点击按键、候选栏和输入法工具区，不触发关闭；点击键盘以外的真实窗外区域仍执行已配置操作。
- 键盘打开时左右侧滑返回优先关闭键盘，不先关闭小窗。
- 将两个上限改为 1、2、4、10 后分别验证生效、FIFO 顺序和设置持久化。
- 检查 `android`、SystemUI 与模块日志，无连续反射异常、任务状态循环或输入事件泄漏。
