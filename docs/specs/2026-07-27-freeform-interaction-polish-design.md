# 小窗交互完善设计（2026-07-27）

## 目标

本轮统一窗外触摸语义、修复挂起恢复位置、降低触发热区对普通应用点击的影响、缩短关闭等待，并增加扇形背景阴影开关。保持 HyperOS 原生小窗动画与系统侧滑优先级，不重启设备。

## 交互设计

### 1. 窗外区域统一

- 以当前全局配置计算的小窗实际边界为唯一分界。
- 上、下、左、右四个方向的所有窗外点按共用 `窗外·单击` 与 `窗外·双击` 设置，不再按方位分区。
- 左右系统手势边缘只在检测到真实移动时让给系统；静止点按仍由窗外操作处理。
- 窗外滑动不执行模块动作，避免返回手势被误判为关闭或全屏。

### 2. 挂起恢复到 A 点

- A 点定义为全局“小窗初始大小与位置”配置计算出的目标矩形。
- 挂起到右上角后，用户点击 mini 小窗触发 HyperOS 原生 `mini -> freeform` 动画。
- 在原生动画创建目标参数时，将动画类型 4 的目标矩形替换为 A 点，并保留 HyperOS 当前恢复缩放值。这样动画直接从 B 点运动并放大到 A 点，不做动画后的跳变。
- 只修改本模块拥有的小窗任务，不影响系统或其他方式创建的小窗。

### 3. 触发热区与应用菜单共存

- 透明角落窗口继续优先接收触摸，避免底部小白条与扇形手势同时触发。
- 若手指形成朝内斜上方手势，继续由模块独占并呼出扇形。
- 若触摸始终未超过手势判定距离并直接抬起，则判定为普通点按：临时移除透明角落窗口，向原坐标回放一次完整点按，再恢复捕获窗口。
- 模块忽略自身回放的事件，避免回放再次触发扇形。明显移动后取消的手势不会回放成点击。

### 4. 窗外操作延迟

- 单击必须短暂等待以排除双击，不能完全为零；判定窗口由系统约 300ms 缩短为 180ms。
- 第二次点按命中时立即执行双击动作，不再等待剩余时间。
- 关闭仍调用 HyperOS 原生标题栏关闭路径，保留原生关闭过渡动画。

### 5. 扇形阴影开关

- 新增“扇形背景阴影”独立开关，默认开启。
- 关闭后仅隐藏扇形区域的大面积径向暗影；应用图标本身的轻微阴影、选中描边和文字提示保留，以维持辨识度。

## 失败保护

- 若系统拒绝注入普通点按，立即恢复捕获窗口并记录日志，不影响后续手势。
- 若 HyperOS 版本没有可修改的动画目标接口，保留原生恢复行为并记录日志，不阻断 SystemUI。
- 所有改动只在 SystemUI 进程内生效，安装后仅重载 SystemUI。
