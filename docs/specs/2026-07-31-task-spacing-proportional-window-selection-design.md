# 任务间距、系统比例小窗与选择吸附设计

> 最终更正：“按比例”不使用物理屏幕比例，也不写死 `5:8 / 2:3`。它等同于用户拖动 HyperOS 小窗右下角调整大小：系统原生小窗形状保持不变，模块只做宽高联动的整体缩放。任务中心的视觉焦点同时需水平跟随手指，不能固定在触发点。

## 目标

在 build124 的任务中心图标模式基础上增加可调图标间距，消除卡片与图标之间的选择空档；同时为竖屏和横屏自定义小窗增加按 HyperOS 默认小窗比例计算的尺寸模式，避免宽高独立调整造成明显拉伸。

本次不改变任务来源、任务数量、任务启动方式、任务中心背景、小窗位置坐标或 HyperOS 原生小窗关闭行为。

## 任务图标间距

- 任务中心设置页新增“图标间距”滑杆。
- 范围为 `0–80dp`，默认 `16dp`。
- 图标中心间距为“任务图标大小 + 图标间距”。
- 调整间距只改变轨道视觉疏密和连续移动距离，不形成不可选区域。
- 卡片模式不读取该参数，继续使用既有卡片间距。
- 恢复任务中心布局默认值时，图标间距恢复为 `16dp`。

## 连续任务吸附

- 手势横向移动超过既有选择启动阈值后，任务中心进入持续选择状态。
- 持续选择状态中，卡片和图标模式都始终选中视觉焦点最近的任务。
- 选择索引使用磁吸动画处理后的实际显示位置计算，而不是使用动画前的原始手势位置。
- 视觉焦点水平跟随手指，卡片或图标仍保持在手指上方，选中项与手指的水平位置一致。
- 手指处于两个任务中心之间时，保留距离焦点更近的一项；没有中间空档。
- 跨过相邻任务的中心分界线后才切换选中项，并继续沿用现有单次震动节流。
- 仅在手指进入下方空白退出区域、收到取消事件或覆盖层关闭时清除选择。
- 松手时启动当前视觉选中任务，继续使用居中系统启动动画。

## 按系统默认比例的小窗尺寸

竖屏和横屏小窗分别保存以下配置：

- “按系统默认比例”开关，默认开启。
- “整体大小”百分比。
- 既有独立宽度和高度百分比继续保留，供关闭比例开关后使用。

比例开关开启时：

- 设置页隐藏该方向的独立宽度和高度滑杆，显示一个“整体大小”滑杆。
- 整体大小是相对 HyperOS 为当前应用生成的原生小窗大小的缩放比例，`100%` 代表系统默认大小。
- 运行时先读取 HyperOS `ActivityOptions` 中的原生小窗边界，再对原生宽高使用同一缩放因子；不交换长宽、不拉伸，也不根据屏幕比例重算形状。
- 竖屏和横屏仅分别保存整体大小与出现位置，小窗的原生形状仍由 HyperOS 和当前应用决定。
- 水平位置、垂直位置、自定义位置总开关和预览继续使用现有逻辑。

比例开关关闭时：

- 隐藏整体大小滑杆，恢复宽度和高度独立调整。
- 开关切换不会覆盖或删除独立宽高值，用户再次关闭比例模式时能恢复原设置。

## 旧配置迁移

- 新比例开关默认开启，整体大小默认 `100%`。
- 已保存的独立宽高值不删除，仅在用户关闭比例模式时继续使用。
- 之前 build125–127 试验性整体大小值不直接解释为新缩放比例；升级到本版时重置为 `100%`，防止因语义变化造成小窗突然过大或过小。
- 竖屏和横屏整体大小范围均为 `50–150%`。
- 新配置读取和实际小窗边界计算必须使用同一组解析结果。

## 运行时边界计算

- `GestureConfig` 根据当前屏方向提供比例开关、整体缩放比例或原独立宽高。
- `HyperOsFreeformBridge` 必须在覆盖 `setLaunchBounds` 之前保存 HyperOS 生成的原生边界。
- 比例开关开启时，以原生边界为基准等比例缩放，再按用户的水平、垂直位置放入当前安全区域。
- 若缩放结果超出安全区域，则宽高继续等比例缩小到可放置范围，禁止单边裁切或拉伸。
- 如果 HyperOS 没有返回可靠的原生边界，本次启动不写入自定义边界，直接交还 HyperOS 管理；禁止退回屏幕比例或写死宽高比。
- 比例开关关闭时，`HyperOsFreeformBridge` 继续使用原独立宽高百分比逻辑。
- 设置页在未知下一个启动应用时，仅预览整体大小和位置变化，不写死或承诺某个应用的实际原生形状。

## 设置页面

- 竖屏小窗卡片和横屏小窗卡片各自增加“按系统默认比例”开关。
- 开关仅在该方向“自定义小窗位置”开启时可操作。
- 比例模式显示“整体大小”，独立模式显示“宽度”和“高度”。
- 位置滑杆始终显示。
- 恢复小窗位置默认值时，两个比例开关恢复开启，竖屏和横屏整体大小都恢复为 `100%`。

## 验收标准

1. 图标间距可在 `0–80dp` 调整，实际轨道间距与设置同步。
2. 卡片和图标模式进入选择状态后，在相邻任务之间移动不会出现无选中状态。
3. 视觉焦点显示的任务与松手实际打开的任务一致。
4. 下方退出区域仍可取消任务中心，不误启动任务。
5. 竖屏和横屏分别具有默认开启的比例开关和整体大小滑杆。
6. 比例开启时，实际窗口宽高比与 HyperOS 为当前应用生成的原生小窗完全一致；关闭后恢复独立宽高。
7. 切换比例开关不会丢失用户原独立宽高配置。
8. 配置提供方和实际小窗启动使用相同的整体缩放值，设置页明确预览大小与位置而不伪造应用原生比例。
9. 单元测试覆盖图标间距范围、视觉索引吸附、原生边界等比例缩放、超限等比例收缩和无原生边界回退。
10. `testDebugUnitTest`、`lintDebug`、`assembleDebug` 通过，新 build 独立归档、安装并热重载 Hook，不重启手机。

## 非目标

- 不增加卡片间距设置。
- 不改变任务中心拖动速度范围或动效风格。
- 不根据应用内容比例动态改变窗口比例。
- 不修改用户设置的小窗位置坐标。
