# 扇形选择与窗外操作优化设计

日期：2026-07-26
基线版本：`8b0c310`
目标环境：HyperOS `OS3.0.317.0.WPBCNXM` / Android 16

## 1. 目标

在不扩大 LSPosed 作用域的前提下，完成四项优化：

1. 扇形菜单只有在手指真正命中图标时才能启动应用；空白处松手只关闭扇形。
2. 扇形呼出距离与图标选择距离分开设置。
3. 窗外单击/双击支持按上下区域自定义动作，但屏幕左右边缘的系统侧滑始终优先。
4. 扇形图标承载形状改为圆角方形，适配 HyperOS 常见的圆角矩形图标。

所有窗外动作仍只作用于由本模块扇形手势启动、且仍处于普通自由窗口状态的唯一追踪任务。

## 2. 扇形手势

### 2.1 两个独立距离

- **呼出距离**：手指从底角开始向上且向内移动，超过此距离后抢占当前手势并显示扇形。继续使用屏幕短边百分比，可调范围 6%–24%，默认 12%。
- **选择距离**：图标中心所在扇形圆弧的半径，同样使用屏幕短边百分比，可调范围 35%–75%，默认 58%。

选择距离必须大于呼出距离加一个图标触摸半径。配置读取时统一校正，避免菜单一出现就意外选中。

### 2.2 精确图标命中

绘制与命中测试共用同一份图标中心几何计算，不再把整个扇形角度区间强制映射到某个应用。

- 手指进入图标的圆角方形命中区时，设置为当前选中项。
- 手指从图标移到任意空白区时，立即清除选中项和应用标签。
- `ACTION_UP` 只在当前仍有有效选中项时启动应用；否则只收起覆盖层。
- 命中区与可见承载底板对齐，可有最多 6dp 的触摸容错，不允许扩张成整个扇区。

### 2.3 图标视觉

- 去掉白色圆形底板，改为半透明圆角方形承载板。
- 普通状态 58dp，选中状态 66dp，圆角 16dp；使用阴影、缩放和描边表达选中，不裁剪应用原图标。
- 3–8 个应用仍沿 12°–82° 圆弧等角排列，左右底角镜像。

## 3. 窗外区域与系统侧滑优先级

### 3.1 以实际小窗边界划分

每次按下前读取追踪任务的 `getScaledBounds()`，使用 HyperOS 当前真实可见边界，而不是配置页保存的原始百分比。

- 小窗内：不处理。
- 窗外上部：`touchY < bounds.top`。
- 窗外下部：`touchY > bounds.bottom`。
- 小窗同高度范围内的左右窗外区域：不触发上下区域动作。

### 3.2 左右边缘始终优先

边缘优先规则覆盖全屏高度，与小窗的大小、位置及上下区域无关。

- 优先使用 `WindowInsets.Type.systemGestures()` 获取左右系统手势 inset，并增加 8dp 安全余量；接口不可用时退回 32dp。
- `ACTION_DOWN` 位于任一边缘保留区时，窗外操作识别器不进入候选、不调用 `pilferPointers()`、不执行关闭/挂起/全屏。
- 因此从左右边缘开始的系统返回手势始终先于窗外单击和双击。
- 底角扇形候选是独立的方向手势：只有“向上且向内”超过呼出阈值才会抢占输入；普通水平侧滑不会激活扇形。

## 4. 上下区域自定义动作

设置页增加四个动作槽位：

| 槽位 | 默认动作 |
|---|---|
| 窗外上部·单击 | 挂起 |
| 窗外上部·双击 | 无操作 |
| 窗外下部·单击 | 关闭 |
| 窗外下部·双击 | 全屏 |

每个槽位可选：`无操作`、`关闭`、`挂起`、`全屏`。

### 4.1 点击判定

- 只有在有效上/下区域且不在边缘保留区的按下才进入点击候选。
- 候选开始后抢占该次触摸序列，保证点击不会透传给底层应用。
- 移动超过 Android `ViewConfiguration` 的 touch slop、超时或出现多指时取消该次点击，不执行任何窗口动作。
- 双击必须发生在同一区域，两次按下距离不超过系统 double-tap slop，时间使用系统 double-tap timeout。
- 为避免第一击先关闭小窗，单击动作必须等待 double-tap timeout 后才执行。第二击成立时取消待执行单击，只执行双击动作。

### 4.2 HyperOS 原生动作

- **关闭**：`MiuiFreeformModeController.exitFreeformTask(taskId, true)`。
- **全屏**：调用当前 ROM 的任务级 `fullscreenFreeformWithoutAnim(taskId, true)`，如控制实现暴露带动画版本则优先使用带动画入口。
- **挂起**：取得当前 `MiuiFreeformModeTaskInfo`，调用任务级 `startPinAnimation(...)`，按小窗中心距离选择最近屏幕边缘作为挂起侧。不使用会影响所有小窗的 `pinAllFreeForm()`。

动作发起后立即停止窗外操作追踪。反射接口不可用或系统拒绝时只记录错误，不尝试对其他任务执行动作，不允许异常逃逸到 SystemUI。

## 5. 组件边界

- `GestureGeometry`：计算触发角、图标中心、圆角方形命中和上下区域，保持纯函数以便单元测试。
- `FanOverlayView`：只使用几何结果绘制圆角方形图标槽位和选中态。
- `OutsideGestureRecognizer`：新增独立状态机，负责边缘排除、上下分区、单/双击时序和移动取消，不直接调用 HyperOS 反射接口。
- `HyperOsFreeformBridge`：提供 `closeTracked`、`fullscreenTracked` 和 `pinTracked` 三个任务级动作，统一处理状态校验与失败隔离。
- `MainActivity` / `ConfigContract` / `GestureConfig`：保存选择距离与四个动作槽位，并在旧版配置缺少字段时自动使用新默认值。

## 6. 验证

### 6.1 自动测试

- 左右角 3–8 个图标中心与绘制坐标一致。
- 手指在图标中、图标间隙、内圈和外圈松手的选择结果正确。
- 选择距离边界校正正确。
- 根据实际小窗 bounds 正确区分内部、上部、下部和两侧。
- 任意 Y 坐标下的左右边缘按下都不会进入窗外点击候选。
- 单击超时、同区双击、跨区点击、超距离点击、多指与移动取消的状态转移正确。

### 6.2 真机验收

- 呼出扇形后，在任意空白处松手都不启动应用；只有手指停在图标上松手才启动。
- 修改呼出距离只影响菜单激活，修改选择距离只改变图标圆弧半径。
- 在屏幕左、右边缘的上部、中部和下部分别侧滑返回，小窗不被关闭、挂起或全屏。
- 默认动作下，上部单击只挂起当前追踪小窗；上部双击无动作；下部单击关闭；下部双击转全屏。
- 四个动作槽位更改后在 SystemUI 中实时生效。
- 普通方式打开的小窗不受影响；追踪任务转为全屏、迷你窗或挂起后不再接收窗外动作。

## 7. 非目标

- 不改写 HyperOS 全局返回手势参数。
- 不为普通方式启动的小窗增加上下区域动作。
- 不为窗外左右同高区域新增动作。
- 本版不为“上部双击”设计新的专用行为，仅保留可配置槽位并默认为无操作。
