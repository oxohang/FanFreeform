# 环形大小、统一名称与快捷方式任务隔离设计

## 目标

- 侧滑环形布局增加独立的整圈半径设置，不改变现有图标大小。
- 底角扇形与侧滑纵向、环形、扇形共用一个“显示选中应用名称”开关。
- 快捷方式只产生最终目标小窗，不再把同包名的现有主任务转成小窗。
- 快捷方式的首帧动画和最终窗口都位于软件设置的目标位置，消除 A 点到 B 点的跳变。

## 实机根因

HyperOS 日志显示，微信扫一扫启动时：

1. 模块先把现有微信 `LauncherUI` 任务转成小窗。
2. 微信 `ShortCutDispatchActivity` 随后创建独立的 `BaseScanUI` 小窗任务。
3. 扫一扫新任务首先使用 HyperOS 默认小窗位置，模块再异步调整到配置位置。

这同时导致两层小窗、A→B 跳动，以及在微信内触发时当前微信界面异常。

## 配置与界面

### 环形大小

- 新增“环形大小”滑条，放在侧滑设置二级页。
- 数值表示环形半径的比例，以当前自动半径为 100%。
- 可调范围 `60%..180%`，默认 `100%`。
- 图标直径继续由“侧滑图标大小”控制。
- 数值过大时，布局优先向屏内移动；若屏幕仍无法容纳，再将实际半径限制到安全范围，不裁切图标。

### 统一名称开关

- 将现有侧滑名称设置迁移为全局的“显示选中应用名称”。
- 开启：底角扇形和侧滑三种布局都只显示当前选中项的名称。
- 关闭：所有手势布局都不显示应用名称。
- 旧“显示应用名称”值作为新开关的迁移值，不重置用户选择。

## 快捷方式启动流程

1. 继续通过小米桌面的 `LauncherApps.startShortcut` 启动快捷方式，保留官方快捷方式权限和行为。
2. 删除对同包名现有任务的预先小窗化和 `launchTaskId` 绑定。
3. 通过 HyperOS 的“强制新任务”启动选项隔离快捷方式调度器，不改写当前微信任务。调度器是透明短暂页面，不纳入模块小窗管理，也不应形成用户可见的第二层。
4. 在 HyperOS 真正目标小窗进入首帧 `startMoveToFrontAnimation` 前，仅对当前待启动快捷方式的包名和时间窗进行匹配。
5. 匹配成功后，同步将动画起点、动画目标和任务实际边界设为软件配置边界，使首帧直接在 B 点淡入/翻入。
6. 最终快捷方式任务被纳入现有小窗外点击管理；短暂调度任务结束时不作为可交互小窗。

## 失败处理

- 无法识别 HyperOS 动画入口时，不修改当前主任务，退回官方快捷方式启动选项。
- 包名、用户或时间窗不匹配时，不改写任何 HyperOS 动画，避免影响普通小窗。
- 快捷方式未生成最终小窗时，按现有 0.5 秒失败检测移除屏幕捕获层。

## 验证

- 单元测试：环形半径缩放、屏内限制、图标选择不受比例改变影响。
- 配置测试：旧名称开关正确迁移，环形大小范围正确裁剪。
- 实机：在微信外和微信内分别打开“扫一扫”；都应只出现一个扫一扫小窗，背景应保持原界面，无 A→B 跳动。
- 实机：逐一检查底角扇形、侧滑纵向、环形和扇形的选中名称开关。
- 实机：小窗外单击/双击、状态栏、控制中心与系统侧滑行为不回归。

## 发布约束

- 从 `0.5.0-stable.8.14-debug` 继续增量修改。
- 新版本必须通过单元测试、Lint 和完整构建。
- 每次构建独立归档 APK。
- 只热重载 SystemUI 和小米桌面，不重启手机。
