# 键盘优先关闭、启动保护与侧滑反向渐隐设计（2026-07-27）

## 目标

修复小窗键盘显示时点击空白区域穿透到底层应用的问题，并让窗外点击形成固定的两阶段行为：第一次关闭键盘，键盘隐藏后的下一次点击再执行小窗窗外动作。同时保护小窗启动动画期间的窗外输入，避免快速点击穿透。侧滑应用列表增加可调的反向取消距离和连续渐隐反馈。

## 键盘优先关闭

- 当前模块管理的小窗处于普通小窗状态且输入法可见时，小窗与实际输入法矩形继续视为可交互区域。
- 点击小窗和输入法矩形以外的空白区域时，从按下开始消费完整手势，不向底层应用传递事件。
- 本次有效单击只调用 HyperOS SystemUI 已有的 `MiuiFreeformModeUtils.hideInputMethodIfNeed()`，不执行用户配置的窗外单击或双击动作。
- 关闭输入法时清除窗外双击识别器中的待处理单击，防止本次点击与键盘隐藏后的下一次点击被合并为双击。
- 等待 SystemUI 的输入法可见状态回调确认隐藏。输入法仍显示期间继续优先执行关闭输入法，不提前关闭小窗。
- 输入法隐藏后，下一次窗外点击恢复现有配置：默认单击关闭小窗，双击全屏；左右侧滑返回继续拥有更高优先级。
- 点击小窗内容或键盘表面不触发本逻辑。

## HyperOS 输入法接口

- 优先在 SystemUI Shell 主执行器调用 `com.android.wm.shell.multitasking.miuifreeform.MiuiFreeformModeUtils.hideInputMethodIfNeed()`。
- 该系统方法先查询当前输入法可见状态，再通过 WindowManager 服务关闭当前输入法，不依赖微信等小窗应用的窗口令牌。
- 类或方法在其他系统版本不存在时，本次点击仍被消费并记录错误；不会为了回退而注入返回键，也不会把事件传到底层应用。

## 小窗启动动画输入保护

- 手势请求启动或复用小窗成功后，立即保存按全局大小、位置和启动缩放计算出的可视目标矩形，并进入最长 6 秒的待匹配保护状态。
- 动画期间任务尚未进入 `trackedBounds()` 时，指针落在目标矩形外即按窗外输入处理并从按下开始消费，防止底层应用收到点击。
- 有效单击产生“关闭待启动小窗”请求。若任务 ID 已可用，立即调用 HyperOS 原生关闭流程；若任务仍未匹配，则保存取消标记，在对应包名的 freeform 任务首次匹配后立即关闭。
- 关闭请求不会等待双击窗口，也不会执行全屏、挂起等其他窗外动作，保证快速取消的响应稳定。
- 指针落在目标矩形内时不作为窗外关闭处理。任务匹配后仍保留 1 秒输入保护并绑定实际任务 ID，覆盖系统提前报告普通状态但动画尚未结束的时段；启动失败、被其他启动替换或 6 秒匹配窗口超时则立即清除。
- 延迟匹配到任务后只关闭包名和启动时间窗都匹配的任务，不影响用户手动打开的其他小窗。

## 侧滑列表反向渐隐

### 方向与距离

- 侧滑超过原有长滑阈值后显示列表，记录此刻指针横坐标为渐隐起点。
- 左侧触发时，继续向右为选择方向、向左为取消方向；右侧触发时镜像处理。
- 选择方向沿用当前逻辑：手指进入列表命中带后按纵向行选择应用。
- 取消方向距离只计算相对渐隐起点的净反向横向位移，垂直移动不增加取消距离。

### 视觉与状态

- 反向距离为 0 时列表透明度为 1。
- 在 0 到配置距离之间，列表按线性比例从 1 连续降到 0；手指向选择方向返回时透明度按相同比例恢复。
- 渐隐期间列表保持存在，不因离开原命中矩形立即关闭，也不选择应用。
- 达到配置距离后立即关闭列表并将本次手势标记为取消；同一次手势重新向内滑动不会重新显示。
- 在渐隐区间抬手只关闭列表，不启动应用。只有手指进入列表、保有有效选择并在有效区域抬手时才启动应用。
- 手指曾进入列表后从纵向顶部或底部移出，仍沿用立即取消；横向朝屏幕边缘移出改走渐隐逻辑。

## 设置与配置

- 侧滑手势二级页面新增“反向取消距离”。
- 范围为屏幕宽度的 `5%–25%`，默认 `12%`，以 `1%` 为步进。
- 新增配置键 `sideReverseCancelPercent`，配置 Provider、运行时配置、恢复默认和主页摘要同步接入。
- 旧版本升级时没有该键的用户自动使用 `12%`。

## 组件调整

- `GestureConfig`、`ConfigContract`、`ConfigProvider`、`ConfigStore`：保存、读取和夹紧反向取消距离。
- `GestureSettingsActivity`、`MainActivity`：增加设置项和当前值摘要。
- `GestureGeometry`：提供镜像的反向距离、渐隐透明度和目标矩形命中纯函数。
- `FanOverlayController`：支持实时设置侧滑列表透明度，移除时取消未完成动画。
- `FanRuntime`：增加输入法优先关闭、待启动保护和侧滑渐隐状态流转。
- `HyperOsFreeformBridge`：暴露输入法原生关闭调用、待匹配保护矩形和延迟关闭请求。
- `OutsideGestureRecognizer`：提供不进入双击等待的即时单击路径，并能清除所有待识别状态。

## 故障保护

- 输入法关闭接口失败时仍消费首次点击，底层应用不会被操作；下一次点击可重试。
- 启动匹配超时后清除延迟关闭标记，禁止未来同包名任务被误关。
- 新启动替换旧待匹配请求时，旧请求和保护矩形一并失效。
- 配置变化或 SystemUI 重载时，侧滑渐隐状态和覆盖层立即清除。
- 渐隐透明度始终夹紧在 0 到 1，不允许负值或越界动画。

## 验证

### 单元测试

- 输入法可见时，窗外第一次点击选择“隐藏输入法”而不是小窗动作；隐藏后下一次点击恢复小窗动作。
- 隐藏输入法会清除待处理单击，不与下一次点击组成双击。
- 启动保护矩形内点击不关闭，矩形外点击生成延迟关闭；超时或包名不匹配不关闭任务。
- 左右侧反向距离完全镜像。
- 反向 0%、中间距离和达到阈值时的透明度分别为 1、中间值和 0。
- 渐隐区抬手不启动；进入有效应用行并抬手才启动。
- 配置值夹紧在 5%–25%，默认 12%。

### 真机验证

- 微信小窗打开键盘后点击空白只关闭键盘且不操作底层；再次点击空白才关闭小窗。
- 抖音、哔哩哔哩等模块小窗打开输入法时行为一致。
- 手势选择应用后在启动动画未完成时快速点击目标窗外，点击不穿透且新小窗使用原生流程关闭。
- 左右两侧列表均在反向滑动时平滑渐隐，返回时恢复，达到设置距离时关闭。
- 分别设置 5%、12%、25% 后，取消距离有清晰差异且持久化正确。
- SystemUI 日志没有连续反射异常或崩溃循环。
