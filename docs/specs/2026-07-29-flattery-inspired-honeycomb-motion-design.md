# Flattery 风格蜂窝布局与跟手动效设计

> 按住滑选的局部压力场已由 `2026-07-29-honeycomb-global-fisheye-design.md`
> 中的全局鱼眼方案取代；本文其余圆形布局、视口和启动逻辑继续有效。

## 目标

参考 Flattery 的圆形应用容器、整体拖动和边缘图标变形思路，独立实现适用于 Hyper手势的蜂窝交互。解决当前应用群轮廓不圆、原始手势继续移动时蜂窝不跟手，以及选中反馈不足的问题。

Flattery 仅作为交互和几何思路参考；不直接复制其源码，新的布局和动画在现有 Java Canvas 架构中独立实现。

## 真正的圆形布局

- 不再使用多个六边形环构造应用群轮廓。
- 先根据应用数量计算圆形面积需要的行数，每行容量使用圆方程的水平截面宽度计算，并在候选行数中选择横纵外径最接近的方案。
- 相邻行错开半个图标间距，保留蜂窝排列，但整体占用区域为圆形。
- 顺序从圆心向外扩展，数量不填满最外行时，将剩余应用对称分配到上下和左右，避免偏向一侧。
- 分行完成后对横纵外径做有限的圆形归一，消除蜂窝晶格天然产生的菱形/六边形轮廓；少于 7 个应用时使用等间距圆环。

## 圆形视口边缘形变

- 蜂窝视口使用明确的圆心和半径。
- 设置页提供 `50%` 到 `100%` 屏幕短边的圆盘直径，默认 `88%`；圆盘大小直接决定边缘缩放和可见命中范围。
- 完全位于圆内的图标按正常大小绘制。
- 进入圆形边缘带的图标按与视口的可见交叠比例缩小，并沿半径方向轻微内收。
- 完全离开圆形视口的图标不绘制、不参与命中。
- 缩放、透明度和内收使用连续曲线，不在边界突变。

## 整体跟手

### 浏览模式

- 从底角或侧滑手势进入蜂窝后，即使原始 `ACTION_DOWN` 发生在蜂窝窗口创建之前，Controller 仍会将后续位移转换为蜂窝内容偏移。
- 应用群与手指保持 `1:1` 移动，使用现有连续物理引擎进行阻尼、惯性和越界回弹。
- 松开第一次原始手势后蜂窝保持，后续触摸继续使用相同的 `1:1` 拖动。

### 按住滑选模式

- 蜂窝页面出现后保持固定，原始手势只移动选择指针，不再平移应用群。
- 命中使用未放大、未让位的稳定图标区域；选中动效不会反向扩大命中范围，因此手指可连续切换应用，不会黏住上一项。
- 松手时仍立即启动当前选中应用；未选中应用则执行现有退场动画。
- 浏览模式仍允许拖动蜂窝页面，两种模式保持清晰分工。

## 选中磁吸与邻居让位

- 手指进入图标稳定命中圆后，该图标平滑放大到现有“选中放大”设置值。
- 按住滑选时以手指为中心生成连续的局部压力场：选中图标最多弹性靠近手指 `10dp`，周围图标最多向外让位 `15dp`，影响在 `1.72` 倍间距内平滑衰减。
- 压力场只改变绘制位置，不改变稳定命中网格；蜂窝圆盘本身不平移，手指仍能可靠切换到相邻应用。
- 切换选中项时，上一个图标弹性归位，新图标连续接管磁吸和邻居让位。

## 启动动画

- 选中确认后，当前图标从其“实际绘制位置”移动到圆形视口中心，而不是从未形变的网格位置开始。
- 图标在移动同时扩张，相邻图标快速退场，背景维持到应用启动提交。
- 动画速度仍受现有蜂窝动画速度设置管理。

## 组件调整

- `HoneycombGeometry`：圆形行宽布局、边缘交叠比例、内收和可见命中几何。
- `HoneycombOverlayView`：实际绘制中心、跟手偏移、磁吸、邻居让位和确认动画。
- `HoneycombOverlayController`：记录原始手势的屏幕坐标，将后续 move/up 连续传给 View，不丢失首个位移量。
- 现有惯性、壁纸模糊、状态栏和启动逻辑保持分离，动效改动不改变小窗/全屏启动方式。

## 验证

- 对 1、7、19、36、60 个应用验证整体轮廓、质心和上下/左右对称性。
- 单独测试图标从圆内、边缘带到圆外的半径、中心内收、透明度和命中变化。
- 回放底角和侧滑进入蜂窝的连续手势，验证浏览模式 `1:1` 跟手、按住滑选模式 `35%` 跟手和应用选择。
- 快速切换相邻应用，验证磁吸、放大、邻居让位、震动去重和命中不抖动。
- 从边缘应用启动，验证确认动画从实际绘制位置开始。
- 满速度拖动和连续惯性期间保持稳定帧节奏，不分配每帧临时对象。
