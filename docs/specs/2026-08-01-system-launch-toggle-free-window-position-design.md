# 系统启动动画开关与小窗自由位置设计

## 目标

恢复 build132 使用的蜂窝全屏中心展开系统动画，不修改它的播放速度，并将是否使用该动画改为开关。同时让竖屏和横屏小窗的水平、垂直位置在设置页中明确表现为可连续调节的精确百分比，不再显示成左、中、右或上、中、下等预设。

## 蜂窝全屏系统动画

- 删除“全屏启动动画速度”五档滑条及 build133 的自定义缩放淡入资源。
- 新增“中心展开系统动画”开关，默认开启。
- 开启时，蜂窝以全屏模式打开应用，使用 build132 原有的中心展开系统动画，不改变系统动画速度。
- 关闭时，蜂窝全屏打开应用使用 HyperOS 默认启动转场。
- 开关同时适用于底角蜂窝和侧滑蜂窝的全屏启动。
- 蜂窝小窗启动、蜂窝自身呼出与确认收束动画均不受该开关影响。
- 保留蜂窝页原有“动画速度”，它只控制蜂窝界面本身，不控制应用系统启动动画。

## 配置迁移

- 使用新的布尔配置键保存“中心展开系统动画”，默认值为开启。
- build133 中的五档速度存储键停止读取和写入，不将其任何数值解释为开关状态。
- 重置蜂窝动效设置时，系统动画开关恢复为开启。

## 小窗自由位置

- 竖屏和横屏分别保留“水平位置”和“垂直位置”两个连续滑条。
- 每个滑条的取值范围为 `0..100%`，步进为 `1%`，显示当前精确数值，例如 `37%`。
- 水平 `0% / 50% / 100%` 分别表示安全可用区域的最左、居中和最右；垂直对应最上、居中和最下。
- 百分比描述的是小窗在“可移动剩余距离”中的位置，因此 `0%` 和 `100%` 均不会让小窗超出安全边界。
- 运行时继续使用已有的连续百分比定位算法，不将数值吸附或四舍五入到预设位置。
- 开启“跟随系统原生尺寸”时，位置预览仍然显示；由于设置页无法在应用启动前获取目标应用的原生小窗边界，此时预览仅用于表示位置，使用已保存的独立宽高绘制示意窗口。
- 关闭对应方向的“自定义小窗”时，滑条继续禁用，实际位置仍交由 HyperOS 管理。
- 保留用户已存储的竖屏、横屏水平和垂直百分比，升级不重置位置。

## 预览与交互

- 小窗预览随滑条实时更新。
- 本版不增加在预览中直接拖拽小窗，避免与页面纵向滚动手势冲突。
- 精确百分比数字和预览共同提供反馈，不再显示“偏左 / 居中 / 偏右”等模糊标签。

## 失败处理

- 中心展开动画开启但当前 HyperOS 不接受覆盖任务转场时，继续发起全屏启动，不因动画失败阻止打开应用。
- 位置配置的异常值在配置边界夹到 `0..100%`，防止升级或手动篡改后小窗越界。

## 验证

- 验证动画开关开启时生成 build132 相同的中心缩放 `ActivityOptions`，关闭时生成普通全屏启动选项。
- 验证底角和侧滑蜂窝全屏启动均使用同一开关，小窗路径不读取该开关。
- 验证竖屏和横屏四个位置滑条均为 `0..100%` 连续值，标签显示精确百分比。
- 验证跟随系统原生尺寸开启和关闭时，预览都按相同的水平、垂直百分比定位；原生尺寸模式下不将示意窗口尺寸作为精确尺寸校验。
- 验证旧位置配置保留，异常值被夹到合法范围。
- 运行单元测试、Lint 和 debug APK 构建，版本号递增。
- 安装到已连接手机，核对已安装版本和 APK SHA-256。
