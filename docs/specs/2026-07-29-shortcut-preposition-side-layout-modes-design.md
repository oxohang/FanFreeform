# 快捷方式预定位与侧滑布局模式设计

## 目标

1. 通过侧滑或底角手势启动微信扫一扫等快捷方式时，不再先在 HyperOS 默认位置显示，再跳到软件设置的位置。
2. 侧滑应用选择新增完整环形布局。
3. 侧滑布局统一为互斥的三种模式：纵向列表、环形、扇形。
4. 保持现有普通应用小窗、窗外操作、系统返回手势和通知栏/控制中心逻辑不变。

## 快捷方式启动设计

### 现状与根因

`LauncherApps.startShortcut` 会先启动快捷方式的分发 Activity。以微信扫一扫为例，HyperOS 随后把分发任务合并到已有微信任务。启动时传入的自由窗位置作用在临时启动阶段，已有微信任务则先使用系统保存的默认自由窗位置，模块只能在任务出现后再次调整，因此形成肉眼可见的 A 点到 B 点跳转。

### 推荐流程：先预定位任务，再启动快捷方式

1. 根据快捷方式包名查找同用户下的已有任务。
2. 如果存在已有任务：
   - 将任务标记为可调整大小；
   - 使用一次 WindowContainerTransaction 同时设置自由窗模式和软件全局配置对应的逻辑边界；
   - 不单独把任务移动到最前，避免改变当前背景应用；
   - 等待 SystemUI 的任务回调确认模式与边界已经提交；
   - 再由小米桌面调用 `LauncherApps.startShortcut`，让快捷方式页面进入已经位于目标位置的任务。
3. 如果没有已有任务，直接使用带自由窗 ActivityOptions 的系统快捷方式启动接口。
4. 任务预定位在 350ms 内未确认时，执行一次当前系统启动方式作为安全回退，不能让快捷方式完全无法启动。
5. 保留任务出现后的最终边界核验，但仅在偏差超过 2px 时修正；正常路径不再产生第二次可见移动。

### 约束

- 不直接构造微信或其他应用的内部 Intent，避免应用升级后失效。
- 不使用全屏遮罩伪装跳转，避免增加触摸延迟或影响系统面板。
- 不把已有任务移动到桌面之上后再启动，必须保留当前应用作为小窗背景。

## 侧滑布局模式

### 配置模型

新增整数配置 `side_layout_mode`：

- `0`：纵向列表，默认值；
- `1`：环形；
- `2`：扇形。

设置页使用单选控件展示“纵向列表 / 环形 / 扇形”，一次只能选择一个。旧配置迁移规则：旧版 `side_fan_list=true` 迁移为扇形，否则迁移为纵向列表。迁移完成后运行时只读取新枚举，不组合多个布尔开关。

### 环形布局

1. 达到侧滑长距离阈值时，以当时手指坐标作为请求圆心。
2. 图标沿 360° 均匀分布，图标顺序与应用列表顺序一致。
3. 圆环半径至少为图标直径的 1.45 倍，同时根据应用数量、图标尺寸和 8dp 最小间距扩大。
4. 使用顶部安全距离、底角保留区和屏幕左右边界计算安全矩形。若请求圆心会让圆环越界，则只平移圆心，不改变手指初始坐标和应用顺序。
5. 当一圈确实无法容纳全部图标时，优先在现有侧滑图标大小允许范围内缩小图标；不创建第二圈，避免选择歧义。
6. 手指位于圆心附近的死区时不选中应用；进入图标的角度扇区和径向命中带后选中对应应用。
7. 手指松开时只有已选中图标才启动小窗；未选中则执行取消动画并关闭选择层。

### 动画与反馈

- 三种侧滑布局共用现有动画速度、呼出幅度、旋转幅度、选择放大倍率、蓝色选择圈和阴影配置。
- 环形呼出：图标从圆心附近向外四散，并旋转到最终角度。
- 环形选择：选中图标使用与底角斜滑一致的放大效果，应用名称按“显示名称”设置显示。
- 环形取消：图标轻微缩回圆心并淡出。
- 纵向列表保留返回屏幕边缘逐渐淡出的行为。
- 环形和扇形禁用反向淡出，手指可在布局范围内自由选择。
- 震动沿用侧滑选择震动开关，每次跨入新的有效图标只震动一次。

## 代码边界

- `ConfigContract / ConfigStore / ConfigProvider / GestureConfig`：负责互斥模式的保存、迁移和运行时传递。
- `GestureSettingsActivity / MainActivity`：负责单选设置和当前模式摘要。
- `GestureGeometry`：新增纯函数实现环形圆心避让、图标坐标和命中测试，并提供单元测试。
- `FanRuntime`：根据模式选择纵向、环形或扇形状态机；只有纵向模式运行反向淡出逻辑。
- `FanOverlayController / FanOverlayView`：绘制环形图标并复用现有动画参数。
- `HyperOsFreeformBridge / ShortcutHostRuntime`：负责快捷方式任务预定位、确认、启动和回退。

## 错误处理

- HyperOS 版本缺少预期的 WindowContainerTransaction 接口时，记录错误并回退到带 ActivityOptions 的系统快捷方式启动，不崩溃 SystemUI。
- 预定位期间目标任务消失时，按“无已有任务”路径启动。
- 侧滑目标为空时不显示选择层。
- 安全区域尺寸异常时回退为纵向列表，保证侧滑仍可使用。

## 验证标准

### 快捷方式

- 微信已在后台时，从任意当前应用启动“微信扫一扫”，只在软件设置位置出现，不经过系统默认 A 点。
- 微信任务不存在时，扫一扫直接在软件设置位置出现。
- 启动前的当前应用仍留在小窗背景，不回桌面。
- 快捷方式启动失败时，350ms 后可正常回退启动，SystemUI 不崩溃。

### 侧滑模式

- 设置页只能选择一种布局，重启 SystemUI 后保持选择。
- 旧版扇形用户升级后仍为扇形，其他用户保持纵向列表。
- 环形在屏幕左右边缘和顶部/底部安全区域附近均完整可见。
- 环形未选中松手只播放取消动画，不启动应用。
- 环形选中放大、名称、震动、蓝圈、阴影和动画速度均服从现有设置。
- 三种布局切换后普通应用与快捷方式都能正常打开小窗。
- 现有系统侧滑返回、输入法、小窗外点击、通知栏和控制中心行为无回归。

## 版本与发布

实现完成后递增版本号，每次构建继续归档到 `release-archive/`。只热重载 SystemUI 和小米桌面，不重启手机。
