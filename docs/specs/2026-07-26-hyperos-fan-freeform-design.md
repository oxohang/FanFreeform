# HyperOS 3 扇形小窗手势设计规格

日期：2026-07-26  
目标设备：小米 2509FPN0BC（popsicle）  
系统：HyperOS OS3.0.317.0.WPBCNXM / Android 16（API 36）

## 1. 目标

实现一个 LSPosed 模块，在已解锁主屏幕的左下角或右下角向屏幕中心滑动时显示扇形应用快捷菜单。用户保持手指滑动选择应用，松手后使用 HyperOS 原生自由窗口启动该应用。

只有通过此手势启动且仍处于普通自由窗口状态的任务启用“随用随走”：第一次点击小窗外部时，该点击被消费，只关闭该小窗，不触发底层应用。

## 2. 已确认的交互

- 左右底角共用一套用户自定义应用列表及排序。
- 默认显示 6 个应用，允许配置 3–8 个。
- 从底角向屏幕中心滑动超过触发距离后立即激活，不需要长按。
- 激活时提供震动反馈；震动可独立开关，默认开启。
- 触发距离可配置，并按屏幕短边比例保存，适配不同分辨率。
- 支持主显示屏横屏和竖屏。
- 锁屏、息屏、副屏及非默认显示屏不触发。
- 小窗初始宽度、高度和位置使用一套全局配置；设置页提供可视化预览。
- 小窗边界会被限制在当前显示区域与系统安全边距内。
- 用户主动将小窗转为全屏、迷你窗或贴边后，立即取消窗外点击关闭追踪。

## 3. 技术路线

模块由配置应用和注入 SystemUI 的 LSPosed 代码组成。配置应用不常驻；SystemUI 进程直接使用 HyperOS WMShell 的全局输入监听和原生自由窗口接口。

### 3.1 输入接入

在 `com.android.systemui` 进程中寻找：

- `com.android.wm.shell.multitasking.miuimultiwinswitch.miuiwindowdecor.MulWinSwitchEventController`
- `registerEventHandler(EventHandler)`

注册模块自己的事件处理器，复用 WMShell 已建立的 `InputMonitor`。`ACTION_DOWN` 位于配置的底角热区时进入候选状态，但暂不抢占系统手势；径向移动超过阈值后调用 `InputMonitor.pilferPointers()`、显示扇形层并震动，从此消费当前手势序列。

所有反射入口均延迟解析并带异常隔离。目标类或方法不存在时只禁用功能并记录日志，不允许异常逃逸到 SystemUI 主线程。

### 3.2 手势状态机

- `IDLE`：等待底角按下，同时处理被追踪小窗的窗外按下。
- `ARMED`：底角候选；移动不足时不干扰系统导航。
- `ACTIVE`：已抢占指针、显示扇形层；移动更新选中项。
- `LAUNCHING`：松手后隐藏扇形层并发起自由窗口启动，等待任务关联。

取消、超时、屏幕状态变化、配置失效或进程异常时统一回到 `IDLE` 并移除覆盖层。

### 3.3 扇形覆盖层

使用 SystemUI 上下文向默认显示屏添加 `TYPE_APPLICATION_OVERLAY` 之外的内部系统窗口类型；窗口为全屏、透明、`NOT_FOCUSABLE | NOT_TOUCHABLE | LAYOUT_IN_SCREEN | LAYOUT_NO_LIMITS`。触摸由 WMShell 输入监听处理，覆盖层仅绘制。

扇形以触发角为圆心，图标沿四分之一圆弧等角排列。选中依据手指极角映射到图标槽位，并设置最小选择半径；未进入有效选择区时松手不启动应用。左右角使用镜像几何。覆盖层展示应用图标、选中放大/高亮和淡入淡出动画。

### 3.4 原生小窗启动

在 SystemUI 进程中反射调用：

`miui.app.MiuiFreeFormManager.getActivityOptions(Context, String, boolean, boolean)`

传入 `noCheck=true` 获取自由窗口 `ActivityOptions`，随后覆盖经安全边界修正的全局启动 bounds，再通过显式 launcher activity Intent 调用 `Context.startActivity(intent, options.toBundle())`。

启动前记录待关联的组件、包名和时间戳。监听 `MiuiFreeformModeController.onTaskAppeared`、`onTaskModeChanged` 等回调，在短时间窗口内将新出现且包名匹配的自由窗口任务关联为唯一的 `trackedTaskId`。新的手势启动成功时替换旧追踪，不关闭其他系统小窗。

### 3.5 窗外点击关闭

追踪存在时，在全局 `ACTION_DOWN` 到达后：

1. 获取 `trackedTaskId` 当前自由窗口的缩放后可见边界。
2. 按下点在边界内时不处理。
3. 按下点在边界外时立即调用 `InputMonitor.pilferPointers()`，消费整个点击序列。
4. 反射调用 `MiuiFreeformModeController.exitFreeformTask(trackedTaskId, true)`。
5. 无论退出调用结果如何均清理追踪；任务回调负责最终状态校验。

普通系统小窗、从最近任务启动的小窗和其他模块启动的小窗不会进入追踪，因此完全不改变它们的窗外点击行为。

当目标任务消失、退出普通自由窗口、切换全屏、进入迷你/贴边状态或用户再次显式启动其他形态时，立即清除追踪。

## 4. 配置与数据

配置应用包含：

- 总开关。
- 已安装可启动应用选择器，支持搜索、添加、移除和拖动排序，限制 3–8 个。
- 触发距离滑块。
- 震动反馈开关。
- 小窗宽度、高度、水平位置和垂直位置滑块及屏幕预览。
- “恢复默认设置”和当前系统接口兼容状态。

配置采用模块私有 `SharedPreferences`，通过带调用方 UID/包名校验的 `ContentProvider` 只向模块自身、Android 系统 UID 和 `com.android.systemui` 提供跨进程读取。图标和标签在配置变化时刷新，不在每次手势移动中进行包管理器查询。

默认值：6 个槽位、触发距离为屏幕短边的 12%、震动开启、小窗宽度为安全区域宽度的 62%、高度为 58%、水平和垂直位置居中。

## 5. 兼容与安全

- LSPosed 作用域仅要求 `com.android.systemui`；配置应用自身无需注入。
- 当前 ROM 的反射签名作为首个适配器；解析器允许方法重载和字段名小幅变化。
- 所有 hook 回调均捕获异常并限频记录；覆盖层添加/移除保持幂等。
- SystemUI 重启后不恢复旧任务追踪，避免误关已有小窗。
- 配置无有效应用或设备处于锁屏、息屏、非默认显示屏时不激活。
- 不申请无障碍、悬浮窗、后台常驻或网络权限。

## 6. 验证与验收

自动验证：

- 手势状态机、左右角极角映射、触发距离和安全 bounds 的单元测试。
- 配置校验与迁移测试。
- Debug 构建中的 HyperOS 反射接口自检和结构化日志。

真机验收：

- 左右底角在竖屏、横屏均可连续完成呼出、滑动选择和松手启动。
- 阈值前不抢占系统返回/主页手势；阈值后扇形跟手且选择稳定。
- 选中应用以用户配置的全局大小和位置打开为原生小窗。
- 点击目标小窗内部不关闭；第一次点击外部只关闭小窗，底层控件不响应。
- 普通方式打开的小窗点击外部不受模块影响。
- 目标小窗转全屏、迷你或贴边后不再自动关闭。
- 锁屏、息屏和副屏不响应手势。
- SystemUI 重启、配置变化和目标应用异常退出后无残留覆盖层或错误追踪。

## 7. 非目标

- 不修改所有系统小窗的默认行为。
- 不实现最近应用自动推荐或左右角独立列表。
- 不接管锁屏、副屏或多显示器。
- 不模拟应用内悬浮窗；始终使用 HyperOS 原生自由窗口任务。
